## Findings not pursued further

None from the reviewer rounds — every blocking finding across all seven rounds was fixed and
re-verified. One deliberate scope decision was made and endorsed (round 6): git aliases, shell
functions, `eval`, and git plumbing-level equivalents (`commit-tree` + `update-ref` achieving the
same effect as `commit` under different subcommand names) are documented as a known, accepted
scope boundary in `procwalk_statement_has_git_keyword`'s own comment, not fixed — closing every
variant of "achieve the same effect under a different name" via text-based keyword scanning is not
a finite problem, and this matches the project's own repeated "no full shell parser" precedent
(`procwalk_has_command_substitution`'s comment; round 5's own reviewer already treating a
git-alias variant of this identical concern as out of scope without objection).
